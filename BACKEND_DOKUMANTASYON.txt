CONVOEASE BACKEND DOKUMANTASYONU
================================

1. PROJE AMACI
--------------
Bu backend, ConvoEase mobil uygulaması için geliştirilmiştir.
Amaç:

- Kullanıcı kayıt ve giriş işlemlerini yönetmek
- Kullanıcının İngilizce seviyesini saklamak
- Senaryo bazlı oturumları yönetmek
- Oturum ilerlemesini kaydetmek
- Oturum tamamlanınca skor ve hata listesini saklamak
- Kullanıcının hata geçmişini sunmak

Not:
Bu backend herhangi bir yapay zeka servisi çağırmaz.
Yapay zeka değerlendirmesi frontend veya harici servis tarafında yapılır.
Backend sadece gelen sonucu saklar.


2. KULLANILAN TEKNOLOJİLER
--------------------------
- ASP.NET Core Web API (.NET 8)
- Entity Framework Core
- SQLite
- JWT Authentication
- FluentValidation
- Swagger


3. PROJE KLASÖR YAPISI
----------------------
Projede sade bir klasör yapısı tercih edilmiştir:

- Controllers
  API endpointlerini içerir.

- Models
  Entity, enum ve DTO sınıflarını içerir.

- Services
  İş kurallarını ve servis mantığını içerir.

- Data
  DbContext, repository sınıfları ve seed işlemlerini içerir.

- Interfaces
  Servis ve repository arayüzlerini içerir.

- Validators
  FluentValidation doğrulama kurallarını içerir.

- Middleware
  Global exception middleware içerir.

- Extensions
  Uygulama genişletmelerini içerir.

- Common
  Ortak exception sınıflarını içerir.


4. VERİTABANI TABLOLARI
-----------------------
Backend aşağıdaki temel yapıları kullanır:

- Users
  Kullanıcı bilgileri tutulur.

- Questions
  Placement test soruları tutulur.

- Scenarios
  Uygulamada kullanılacak sabit senaryolar tutulur.

- UserSessions
  Kullanıcının başlattığı konuşma/yazma pratik oturumları tutulur.

- UserMistakes
  Tamamlanan oturumlara ait hata kayıtları tutulur.

- RefreshTokens
  Refresh token kayıtları tutulur.


5. SENARYOLAR
-------------
Sistemde sadece 5 senaryo bulunur:

1. Cafe Conversation
2. Hospital Visit
3. Shopping
4. Hotel Check-in
5. Job Interview

Bu senaryolar uygulama açıldığında seed edilir.
Fazladan senaryo varsa seed mantığı onları temizler.


6. KULLANICI SEVİYELERİ
-----------------------
Kullanıcı seviyeleri:

- Beginner
- Intermediate
- Advanced

Kurallar:

- Kullanıcı başlangıçta seviyesiz olabilir
- Placement test sonrası frontend seviyeyi backend'e gönderir
- Kullanıcının seviyesi Users tablosunda tutulur


7. AUTH YAPISI
--------------
Sistemde rol bazlı yapı yoktur.

Yani:
- Admin yok
- Role sistemi yok
- Sadece kullanıcı vardır

Ancak kullanıcı güvenliği devam eder.
Bunun için JWT kullanılır.

Token yapısı:

- Access Token süresi: 15 dakika
- Refresh Token süresi: 7 gün

Refresh token kuralları:

- Her refresh işleminde eski token iptal edilir
- Yeni refresh token üretilir
- Eski token tekrar kullanılamaz


8. GÜVENLİK
-----------
Protected endpointlerde kullanıcı doğrulaması yapılır.
Her kullanıcı sadece kendi verisine erişebilir.

Örnek:
- Bir kullanıcı başka bir kullanıcının session verisini göremez
- Bir kullanıcı başka bir kullanıcının hata geçmişini göremez

Şifreleme:
- ASP.NET PasswordHasher kullanılır


9. API ENDPOINTLERİ
-------------------

AUTH
----
POST /api/auth/register
  Yeni kullanıcı kaydı oluşturur.

POST /api/auth/login
  Giriş yapar ve access token + refresh token döner.

POST /api/auth/refresh
  Refresh token ile yeni token üretir.

POST /api/auth/logout
  Kullanıcının refresh tokenlarını iptal eder.


QUESTIONS
---------
GET /api/questions
  Placement test sorularını döner.


USERS
-----
POST /api/users/level
  Kullanıcının seviyesini günceller.


SCENARIOS
---------
GET /api/scenarios/allowed
  Kullanıcının seviyesine uygun senaryoları döner.


SESSIONS
--------
POST /api/sessions
  Yeni session başlatır.

POST /api/sessions/complete
  Session tamamlar.
  Skor ve hata listesini kaydeder.
  Gerekirse seviye ilerletir.

PATCH /api/sessions/{id}/progress
  Session devam ederken ara kayıt alır.
  LastProgressJson alanını günceller.


MISTAKES
--------
GET /api/mistakes?scenarioId=&page=&pageSize=
  Kullanıcının hata geçmişini listeler.
  İstenirse belirli senaryoya göre filtrelenebilir.


10. SESSION KURALLARI
---------------------
- Aynı anda birden fazla session olabilir
- Score alanı başlangıçta null olabilir
- Session tamamlanınca skor set edilir
- Progress json sadece session tamamlanmamışsa kaydedilebilir
- Tamamlanmış session'a tekrar progress kaydı yapılamaz


11. LAST PROGRESS JSON
----------------------
Bu alan, session bitmeden ara ilerlemeyi saklamak için kullanılır.

Kurallar:
- Geçerli JSON olmak zorundadır
- Maksimum 10 KB olabilir
- Geçersiz JSON gelirse 400 döner


12. MISTAKE YAPISI
------------------
Her mistake kaydı:

- SessionId
- ErrorType
- WrongSentence
- CorrectionText

alanlarını içerir.

Hatalar kullanıcı bazlı çekilir.
İstenirse scenarioId ile filtrelenebilir.


13. LEVEL PROGRESSION
---------------------
Bir kullanıcı mevcut seviyesindeki tüm senaryolar için en az bir tamamlanmış session oluşturduysa bir üst seviyeye geçer.

Önemli:
- Skor önemli değildir
- Tamamlanmış olması yeterlidir

İlerleme:
- Beginner -> Intermediate
- Intermediate -> Advanced
- Advanced -> ilerlemez


14. VALIDATION
--------------
FluentValidation kullanılır.

Doğrulanan alanlar:

- Email formatı
- Şifre kuralları
- Score aralığı
- Gerekli alanlar
- Enum değerleri
- JSON doğruluğu

Şifre kuralları:
- Minimum 8 karakter
- En az bir büyük harf
- En az bir küçük harf
- En az bir rakam


15. HATA YÖNETİMİ
-----------------
Global exception middleware kullanılır.

Standart hata cevabı:

{
  "message": "Hata açıklaması",
  "statusCode": 400
}


16. SWAGGER KULLANIMI
---------------------
Swagger test amaçlı kullanılabilir.

Önerilen test sırası:

1. Register endpointi ile kullanıcı oluştur
2. Login ile token al
3. Questions endpointini dene
4. Users/level ile seviyeyi güncelle
5. Sessions ile yeni session oluştur
6. Progress kaydet
7. Session complete ile bitir
8. Mistakes endpointi ile hataları listele

Not:
Swagger'da auth görünümü sadeleştirilmiştir.
JWT güvenliği sistemde devam etmektedir.
